# CHART-DESIGN — 譜面生成の設計

`scripts/generate-charts.py` の設計根拠をまとめる。生成器の冒頭 docstring が
版ごとの変更履歴の正本で、この文書はその要約。曲別の方針は生成器内 SONGS の
メタデータに置く。両親指制約の正本は `scripts/check-two-thumb.py`。

## 土台（v2、維持）

- 拍グリッドは librosa の実測拍列に沿わせる（回帰直線＋残差の移動平均で平滑化し、
  16分スロットは隣り合う拍の間を4等分して補間。累積ドリフトが出ない）。
- 選んだスロットの近く（±38ms）に強いオンセットピークがあればスナップする
  （v2 は ±50ms。遠いピークは別のリズム事象のことが多いため v3 で狭めた）。
- 密度は小節ごとの RMS エネルギーに連動。節の切れ目（FEVER 境界・エネルギーの
  落ち際）の直前には小さな休符を作る。
- FEVER 区間は密度を上乗せする（オーナー指示「フィーバー中はノードも多くして、
  気持ちよく叩けるように」）：計画エネルギーの底上げ＋16分パターンの確率アップ
  （plan_phrase）と、間引きでの FEVER 優先（thin）で効かせる。
- charts.json に実測拍列（beats）も保存し、単体テストがズレを検証する。
  表示 BPM は回帰から求めた実測値（整数）。FEVER 区間は固定値のまま。

## 譜面 v3 — フレーズ単位のパターン割り当て

- ノーツの置き方を「強度順の貪欲ピック」から「フレーズ単位のパターン割り当て」に
  変えた。半小節を単位に、階段／波／交互／交差／縦連／トリル等の型を意図的に
  割り当て、型の連続として譜面を組み立てる。
- サビ（FEVER）のフレーズでは、最初のサビのパターンの並び（モチーフ）を後の
  サビで再登場させる。2回目はレーン鏡像、3回目は末尾も変化させる。サビ内でも
  後半は前半のパターンを繰り返す。
- 同時押し：サビの小節頭など特に強い拍に2レーン同時押し（hard 中心、normal は
  ごく強い拍だけ、easy はなし）。
- 長押し：オンセットが長く空き、その間も音が鳴り続ける場所（持続音）に置く。
  長さは拍単位。easy は短く少数で長押し中は他のノーツなし、normal は長押し中の
  他レーンノーツが少ないものだけ、hard はサビ中心に長押し＋他レーンタップあり。
- 入れ子（easy ⊆ normal ⊆ hard）は (時刻, レーン) で維持する。normal は hard の
  8分位置の骨格、easy は拍位置のみ。
- 同一レーン3連続は原則禁止。例外は hard の縦連（間隔 170ms 以上の3連まで）。

## 両親指前提（譜面 v4）

オーナー指示「基本両手（両親指）でやることを前提にやりやすい譜面に」。
レーン 0・1 を左親指、2・3 を右親指が受け持つ前提で、両親指のハード制約を
生成に組み込んだ（制約の正本は `scripts/check-two-thumb.py`）：

- C1 同時押しは左右に分かれるペアだけ（同側ペア禁止）。
- C2 長押し中は拘束側のノーツを置かない（帯の中は反対側だけ。同時押しの
  ある時刻をまたぐ長押しも置かない）。同時ホールドは同側同士で重ねない。
- C3a 16分の連なりで同側3連を作らない（トリルは左右交互に変更、wave16 の
  形も同側3連が出ない形に変更。フィット時の罰金＋生成後の修復でも担保）。
- C3b 同側2レーン交互（片手トリル）は8分以下の速さで4連まで
  （フィット時の罰金＋生成後の修復で担保）。
- C4 同一レーン連続は従来ルール（hard の縦連だけ例外）を維持。

生成後は check-two-thumb.py の check_charts() で全譜面を検証し、違反が
あれば charts.json を書き出さずに終了する。

## 譜面 v5 — 特徴量レイヤーと主レイヤー選択

- V5-1 特徴量レイヤー：HPSS で打撃成分（ドラム）と持続成分を分け、持続成分の
  旋律帯域（600〜6000Hz）＝メロディ／声帯域（600〜3000Hz）×有声度＝ボーカル
  の帯域別オンセット強度と、pyin の F0 をスロット属性に持つ。ゲートの物差しは
  レイヤー強度を全帯域 strength の分布へ順位写像した eff（順位が同じなら値が
  同じになるため、既存の閾値がそのまま意味を持つ）。
- V5-2 主レイヤー選択：フレーズごとに主パート（drums/melody/vocal/mixed）を
  決め（曲別バイアス＋サビの指定レイヤーへのボーナス。サビは連続フレーズを
  グループとして1回だけ決める。通常フレーズ間はヒステリシス 0.08）、
  パターン選択・同時押し・密度の床が見る strength を主レイヤーの eff に切替。
- V5-3 音高コンター：主レイヤーがメロディ/ボーカルのとき、F0 の動きとレーン
  移動の方向の一致を fit コストに反映（|ΔF0|≥1半音：同方向 −0.20／逆方向
  +0.45／不動 +0.15。同音反復は jack のゲート緩和にも使う）。
- burst（16分パターン）のゲートだけは主レイヤーで測らない：持続成分の
  フラックスは16分位置のすべてで高く出て常時開いてしまうため、根拠の
  取り方を曲別に選ぶ（SONGS の burst_basis: main / drums / main65）。
- 特徴量の照合と指標の道具は scripts/analyze-layers.py。

## 譜面 v6-1 — 持続/打撃の分岐と非サビモチーフ（テンプレート v1.6.0）

- V6-1a 持続/打撃によるパターン分岐（旧称 V5-4）：スロットに持続度
  （harm_rms を曲内95パーセンタイルで正規化した sustain）を格納し、フレーズの
  主レイヤーと組み合わせて sustain_mode（sustained / percussive / None）を決め、
  plan_phrase のパターン確率（jack・burst・sparse の比率）と長押し候補の
  優先度・可否に反映する。持続的（melody/vocal かつ持続度高）→ stair/wave と
  長押しを優遇。打撃的（drums または持続度低）→ jack を優遇し長押しを抑える。
- V6-1b 非サビ反復セクションのモチーフ再利用：FEVER 外のフレーズ同士の類似度
  （strength 列・energy・F0 コンターのシグネチャのコサイン類似度）を曲内相対の
  閾値で判定し、再登場フレーズは初出のパターン計画を再利用する。2回目は鏡像、
  3回目以降は末尾変化（サビの従来扱いに倣う）。サビは従来のモチーフ処理のまま。

### v6-1.1（NK-S003 実曲トライアルの所見から）

- モチーフ最小長：非サビモチーフ再利用の対象を「2小節以上のフレーズ同士」に
  限定した。1小節だけのフレーズはシグネチャが短すぎて、無関係でも類似度が
  高く出て組になってしまうため（umi で bars 31 ↔ 63 の1小節組、類似度
  0.883 が発火した実例）。閾値（絶対下限・相対下限）は従来どおり。
- normal／easy の密度下限ガード：thin の目標総数は「最も候補の少ない
  レーンが2割を確保できる量」で決まるため、パターン配分の変化で1レーンの
  候補だけが減ると、プール総数がほぼ変わらなくても全体が大きく割り込む
  （umi normal：プール 401→381 なのにレーン0候補 87→66 が目標 410→321 を
  招き、最終 375→293 の −22% になった実例）。そこで、thin の目標が cap
  でなく最少レーン由来で決まった難易度に限って、間引き後に候補プールの
  DENSITY_FLOOR_RATIO 倍を下限とし、割り込んだ分は落ちた候補を強さ順に
  戻すガード（fill_density_floor）を入れた。cap 律速の曲には発動しない。
  戻す候補は上位難易度の確定集合の中だけ（入れ子維持）、レーン割合・
  最小間隔・同一レーン3連・両親指の同側連なりを見て安全なものだけにし、
  戻した後は修復を回し直す。

### v6-1.2（v6-1.1 の残差への上流対策）

- 8分位置のレーン配分を上流で均す：Realizer が 8分位置（sub 偶数）だけの
  レーン別カウント（eighth_counts）を別に持ち、フィットのコストにその分布
  均衡（EIGHTH_BALANCE_W=2.0。全体分布の重み 6.0 の 1/3）を加えた。
  normal の候補プールは hard の8分位置サブセットなので、全体分布が検証範囲内に
  あっても8分位置だけレーンが偏ると、thin の最少レーン律速で normal 全体が
  削れる。下流の密度下限ガード（v6-1.1）に頼る前に、プールの最少レーン自体を
  保つのが狙い。ガードは安全網として残す。
- sustain 閾値の曲別上書き口：sustain_mode 判定の閾値（従来は絶対定数
  SUSTAIN_HI=0.50 / SUSTAIN_LO=0.30）を、SONGS メタデータの sustain_hi /
  sustain_lo で曲別に上書きできるようにした。未指定なら従来値で挙動不変。

## 譜面 v6-2 — フリックの生成器統合（既定 OFF）

曲別メタデータ `flick: True` の曲だけ。NK-S006 v1.4.2 の確定方針
（rework-chorus-patterns.py）を生成器ルール化した。割合ありきの機械変換は
しない。フリックは音楽的な「決め」だけに置く：

- サビ内は第1サビで決めた位置（サビ入り・フレーズ頭・強拍アクセント・
  F0 跳躍・フレーズ末）を全サビへ適用し、サビ外はフレーズ頭の
  強アクセント／クライマックス頭／サビ直前の一打だけに絞る。
- 適格性と難易度別最小間隔（easy 4500ms / normal 2400ms / hard 1400ms、
  下限 1200ms）は NK-S006 の実績どおり。
- 出力形式は NK-S006 と同じ `[time, lane, 0, "flick"]`。
- テンプレート側ランタイム（src/game）は v1.7.0 からフリック標準対応
  （入力・判定・表示・合成音・キーボード対応とノーツ速度調整を NK-S006
  試作から移植）。それ以前のエンジンで作られた作品では ON にしないこと。

### 標準化改訂（v1.7.0）— サビ間伝播の構造アンカー化とサビ外ゲート厳格化

NK-S006 試作のオーナー暫定OKを受けて標準化。NK-S003 トライアルで実証
された欠陥への対策：

- 伝播方式を、FEVER 開始点からの絶対拍オフセットから「サビ内のフレーズ
  構造上の位置（サビ内フレーズ順＋フレーズ先頭拍からのオフセット）」へ
  変更。絶対方式はサビの長さや入り拍が違うと位置がずれる／落ちた
  （一致：yoru 4/4、keiyo 3/5 で +1拍ずれ、umi 1/9）。
  構造方式の実測（NK-S003、第2サビへのアンカー適用率）：keiyo 7/12、
  umi 10/15、yoru 4/5。残りの落ちは、対応する構造位置にノーツ自体が
  無い（absent）か、その位置のノーツが適格外（同時押し・長押し・同レーン
  250ms 規則）によるもの——伝播は既存ノーツへの印付けであり、ノーツ自体を
  構造位置へ強制配置はしない設計のため。
- サビ外ゲート厳格化：総数はサビ内総数を超えない、1フレーズに1つまで、
  クライマックス頭も最強クラス（thr93）のみ、曲頭5秒は置かない。
  実測（hard 換算の選択総数）：umi サビ外 12→6（サビ内 11→16）、
  yoru はイントロ直後 2.995 秒のフリックが消滅。

### 伝播フォールバック修正（テンプレート v1.8.0、NK-S006 v1.4.16 で先行）

構造アンカーに対応するノーツが無いサビでは、アンカーがそのまま落ちて
「そのサビだけフリックが無い／極端に少ない」状態になっていた。対策として、
対応ノーツが無いアンカーは ±1 拍以内の最寄りの適格ノーツへ寄せて印を付ける
（フォールバック）。寄せた先でも難易度別最小間隔を満たすこととし、間隔の
優先順位は「正確な構造位置 ＞ フォールバック ＞ サビ外」の3段で判定する。
フォールバックでも救えない場合に限り、サビに1つもフリックが残らない曲だけ
救済範囲を広げる。NK-S006 実測では easy の最終サビにフリック 0 が残るケースが
あり、オーナー判断で許容した（生成器の救済はここまで）。

## 譜面 v6-3 — フリック先決めと手の流れ検証（テンプレート v1.8.0、NK-S006 v1.4.18 で先行）

オーナー所見「譜面でフリックのある場所が気持ちよくない」への対策。従来は
間引きの後に残ったノーツへフリックを印付けしていたため、フリックの直前に
ノーツが詰まって「構える間」が無かった。v6-3 では順序を逆にする：

- フリック先決め（ピン留め）：フリック位置を間引きより前に確定し、ピンした
  ノーツは後の間引き・検証でも落とさない。
- 直前ウィンドウの間引き：フリック直前の easy 2.0 拍 / normal 1.5 拍 /
  hard 1.0 拍の範囲は、ピン以外のノーツを間引いて構える間を作る。
- 直後の回復：フリック直後 300ms は同レーンにノーツを置かない。
- flick_budget：曲別メタデータで難易度ごとのフリック総数に上限を置ける
  （任意。未指定なら上限なし）。上限で落とす場合はサビ外・弱い位置から落とす。
- 手の流れ検証（生成後の検証段）：各フリックについて直前 500ms の密度が
  難易度別上限（easy 1 / normal 2 / hard 3）を超えていたら、フリックを
  ±1 拍へずらす（shift）か落とし（drop）、理由をログに残す。実データでは
  未発動でも、強制テストで動作を担保する。
- テンプレート標準化時の追加ガード：上記の間引きでレーン配分が崩れて
  validate() のレーン占有率（LANE_MIN_SHARE〜LANE_MAX_SHARE）を割る場合は、
  その間引き自体を行わない（占有率を割る変更はスキップし、件数を逐次追跡）。
  NK-S006 の3曲では発動しなかったが、テンプレートのサンプル曲（track-a、
  flick ON のスモークテスト）で実際に必要になった。

不変条件は維持する：flick OFF の出力は v1.7.0 とバイト同一
（v1.8.0 標準化時にサンプル2曲で md5 一致を確認済み）。
